# Audience implementation slice

Implements the next independent parts of PRD REQ-027–029. The full GA register and all production gates remain authoritative. No provider access or spending is required for these data operations.

1. Fix the cancelled campaign review transition under its existing row lock; prove the former incorrect 200 response and the corrected 409 response, then verify Chromium cancellation/reload.
2. Add tenant-isolated lists, tags, typed custom-field definitions, memberships and immutable segment versions. Preserve contacts and all consent/suppression history. Composite tenant keys and forced RLS apply to every new table.
3. Build a bounded, versioned rule AST for lists, tags, string/number/boolean/date attributes and genuinely observed engagement. Validate field types, depth, node counts and identifiers. Compile only parameterized, allowlisted SQL; missing values never accidentally satisfy negative comparisons.
4. Implement current-membership checked, idempotent APIs for definitions, contact organization and segment versions. Preview returns evaluation time, matched/eligible/excluded counts. Freeze snapshots with rule version, sorted contact IDs, consent versions, eligibility reasons and digest. Preview or snapshot creation never grants opt-in or dispatches mail.
5. Provide usable audience controls for organization and segment construction, including empty/error states and disabling repeated work. CSV mapping/bulk throughput follows this slice; arbitrary JSON is not the main UI.
6. Verify wrong-tenant IDs, malformed/injected rules, concurrent version conflicts, missing typed values, suppression changes after snapshots, repeated requests and actual browser navigation. Run test/lint/typecheck/build/HTTP checks, synchronize Desktop/mail, publish tested source, and inspect CI.

Field types and operators are conservative implementation details because the PRD does not enumerate them. Engagement data requires authenticated provider-event provenance; no public API may invent events, and empty observed data is shown as empty. Campaign dispatch must re-evaluate current eligibility; immutable snapshots do not waive that pending dispatch requirement.
