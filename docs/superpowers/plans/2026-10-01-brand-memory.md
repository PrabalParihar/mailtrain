# Versioned Brand Memory implementation plan

Goal: deliver REQ-007 tenant-scoped source chunks, source-removal exclusion and inspectable generation provenance, preserving REQ-006/009/063 and the complete Baseline A. Authoritative spec: locally materialized Mailcraft-Development-PRD-v2.0.md, REQ-007, domain brand_sources/brand_memory_chunks and TECH-090/092. Native execution remains explicitly authorized; use executing-plans with one fresh whole-slice reviewer and one Important RED→GREEN pass.

Design: immutable manually approved text sources attach to one exact confirmed brand version. Forced tenant RLS and composite FKs isolate sources/chunks. Source removal is an irreversible retrieval tombstone, not a claim of physical erasure across backups/vendors. Source text is never fetched automatically, promoted to system instructions, mixed with contacts/secrets, or cached across tenants. New retrieval reads live active sources; already obtained/in-flight context is historical and cannot be recalled. Historical provenance stores IDs/digests/method/time rather than source text. Generation uses the selected immutable kit and this bounded context immediately before its provider attempt. No provider call or embedding cost is introduced by local fixtures.

Ruling: deterministic lexical retrieval v1 is the bounded no-provider development implementation; embedding_model/version remain null and no semantic similarity claim is made — configured embeddings/evaluation remain GA work — cost if wrong: a versioned retrieval adapter and funded evaluation are needed. Sources require an explicit rights/no-PII/no-secrets acknowledgment and allowed_usage=approved_context; this is an owner assertion, not verified licensing.
