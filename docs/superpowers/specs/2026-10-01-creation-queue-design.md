# Durable creation queue foundation

After the reviewed membership slice, complete the independent queue foundation for REQ-006/009/010/052/060/064 and TECH-011/012/061/070. The PRD remains Baseline A; provider/account configuration and production acceptance are separate from development evidence.

PostgreSQL owns operation state, finite retry budgets, immutable attempt evidence and reservations. Existing queued brand extraction and email generation become separate Redis/BullMQ queues containing only workspace/operation IDs. Durable reconciliation recreates lost wake jobs; duplicate enqueue and stalled BullMQ jobs cannot create another external effect. Per-workspace fair bounded admission must be enforced in SQL, with finite global and workspace concurrency/backlog limits. No ordinary web principal or queue payload supplies role or private provider context.

A narrow scheduler discovers ID-only due work. A separately restricted worker obtains token-bound leases and context through narrow functions; web runtime must not become the production worker identity. Every admission orders workspace before member/key/operation locks and checks current membership, key scopes/revocation and database-clock expiry after locking. Recheck current cancellation/authority immediately before committing an external-attempt start. No database transaction spans a provider call. A crash before a recorded start is safely recoverable; a recorded external start without a definitive result is reconciliation-required and never automatically repeated. Already released context cannot be recalled.

Generation has a versioned finite120-second budget and at most three proven-safe transient attempts; rate deferrals respect Retry-After without spending failures. Refusal/policy/invalid output is terminal. A generic timeout or transport loss after a request may have reached the AI provider must retain its reservation and expose reconciliation-required; no invented provider-idempotency guarantee or invoice reconciliation. Definitive provider failures may retry only under the adapter's documented safe contract. Unsupported/configuration failures occur before an external start and release unused reservations. Successful/chargeable outcomes consume once; cancellation before external start releases once. Late/stale worker acknowledgments cannot overwrite a newer token/state or apply a draft.

Brand extraction may safely retry bounded public read requests; preserve existing public HTTP/HTTPS validation, pinned DNS and bounded SSRF controls and its truthful proposal-only result. Cancellation is durable and checked before each external read and settlement. Existing generation proposals never silently replace a user's draft or dispatch mail.

Production worker startup must require nonempty same-build full13-gate evidence, intended separate private service credentials, approved provider/model/finite allowance and explicit mode. Local strict-loopback fixtures may use owned PostgreSQL/Redis/HTTP and process interruption to exercise recovery, never real provider requests or paid work. Actual distinct-process restart, Redis loss, fairness/capacity, grant revocation/cancellation races, repeated wakeups, stale tokens and ambiguous charged-attempt reservation retention are acceptance tests for the development slice. Production load/outage/identity/provider/economics evidence remains required.

Version1 engineering bounds: global2/workspace1 live claims,1,000 unfinished creation jobs per workspace, scheduler batch25,30-second leases renewed every10seconds and five-second external-start grants. First claim starts a120-second execution window; expired external generation start is reconciliation-required, never a replayable lease. Separate BullMQ queue names are lettercape-generation-v1 and lettercape-brand-extraction-v1; ordinary BullMQ attempts=1 leaves business retry decisions in SQL. UUID-only job IDs join workspace and operation with a hyphen. No BullMQ Pro subscription is introduced.

Preserve the existing public operation states queued/running/succeeded/failed/cancelled/cancel_requested. An unresolved charged-provider outcome ends with error.code=AI_RECONCILIATION_REQUIRED and explicit retained-accounting metadata; its display must never suggest safe automatic retry. Cancellation after an unresolved external start may end cancelled while still requiring accounting reconciliation. No new frontend polling state can loop indefinitely. Known successful generation consumes its already reserved local generation unit once; this is not vendor invoice reconciliation or an approved public price. A terminal unattempted/configuration failure releases; errors after an external start retain reservations unless the selected adapter has definitive accounting evidence.

References: [BullMQ retry behavior](https://docs.bullmq.io/guide/retrying-failing-jobs), [stalled jobs](https://docs.bullmq.io/guide/jobs/stalled), [idempotent jobs](https://docs.bullmq.io/patterns/idempotent-jobs). BullMQ retry/stall machinery only wakes durable SQL work; it cannot decide external-effect replay.
