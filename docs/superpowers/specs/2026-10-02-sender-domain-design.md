# Provider-bound sender drafts and DNS evidence design

Build the next local vertical slice for REQ-032/033/035/050 and TECH-080/JRN-03. Full65/13baseline stays binding; this increment is partial development and does not replace live provider/received-message acceptance.

## Intended behavior and scope
Owner/Admin saves a versioned sender draft with provider (ses/resend/sendgrid/mailgun), account label (an operator reference, never credential/proof), provider region, from address/name and optional reply-to. Canonical domain is derived server-side from the from address; material changes produce a new immutable version. No external account/identity is created. Provider connection/account verification, issued records, signing/alignment and production readiness remain unavailable until configured; views explicitly expose connection_status=not_connected and sending_enabled=false.

Owner/Admin can request a bounded read-only DNS observation for the acknowledged sender version. Query only TXT at the exact canonical from domain and _dmarc.<domain>; never guess DKIM selectors or Return Path. Split TXT strings join within each RR. Show exact bounded observed records, timestamp and single/multiple/missing/unavailable status. The result is local DNS record discovery only, not full SPF evaluation, organizational-domain DMARC discovery, domain ownership, alignment or received authentication. Duplicate SPF warns against publishing another/conflicting record. Exact provider-issued DNS values are absent, not synthesized. No DNS mutation/replacement, message send or provider-success status is offered.

## Architecture and contracts
Strict Zod SenderDraftInput / SenderVersionInput / SenderView / DNSObservation schemas.100-character name/account label,254-character email,40-character region,100-character from name; emails/domains normalize IDNA and reject control/URL/IP/single-label forms. Provider region is retained explicitly, not inferred as global readiness. JSON views reject unknown/private credential fields. DNS envelope: up to40records per queried owner, each4096characters, combined32KiB;5-second owned resolver deadline/cancellation; safe error categories. Reserved/private local names never query internal DNS.

sender_identities current row plus sender_identity_versions immutable snapshots and domain_checks immutable version-bound evidence, all composite workspace keys/FKs and forced RLS. Runtime cannot forge connection/readiness or edit/delete historical captures; typed guard verifies exact next version/current manager; no migration invents verification evidence. API action manage for all sender surfaces, signed actor/workspace pages, sender:read/sender:write scopes (explicit new scopes), current membership/key/session after waits/receipt and after DNS work. POST create/version/check idempotent and exact expected_version; no-op does not append a version. Old receipts describe originals while detail rereads current truth. Rate bound10DNSchecks/minute/workspace; idempotent replay consumes no new query/admission.

Dedicated /app/delivery sender panel: typed paged list, explicit editor/load, original saved version separate from invalid working text, scoped invalid/body/key recovery and honest initial/empty/error/stale states. Current-role/workspace changes fence delayed responses. DNS history labels old-version/stale evidence (15minute display freshness; never a send authorization). Provider guidance links official docs; account setup appears unavailable. Form recovery follows the reviewed bounds/roundtrip/guard contract and maxLength.390px controls, empty/errors/repeated clicks/lost acknowledgments/reload/CAS/current-role denial/navigation/storage exceptions verified in Chromium.

## Required future boundary
Read-only provider adapters must retrieve authenticated account/region/identity and exact issued DNS records from the intended configured connection, bind evidence to sender version and connection generation, and verify readiness before any campaign. Received raw MIME must prove required aligned authentication, DKIM and RFC8058coverage; no fabricated green can substitute. Private credentials, KMS, legal sender policy/allowed test recipient and funded provider remain external blockers; no spending or test send here.

## Evidence and alternatives
Selected incremental approach: durable sender drafts + truthful independent DNS observations; preserves useful setup work while account-bound verification is absent. A guessed generic SPF/DKIM wizard would violate TECH-080. Deferring all sender code until accounts exist would leave independent contracts/UI/storage unfinished. This design chooses no new dependency or external activation.
