# Frozen workspace template catalogue

Purpose: advance the full PRD REQ-011 journey from a reusable frozen email to an independent editable draft. This is an independent development slice, not acceptance of an entire requirement or production gate. The user directs continuous implementation with disjoint workers and permits qualified corrections on repository main.

A saved template references an existing immutable same-workspace revision and its artifact hash. It does not store a second EmailSpec, automatically change brand, or follow later edits/restores. Metadata includes its name, source title/email/revision number, frozen brand/locale/direction/editing mode, state, version and timestamps; catalogue/detail responses exclude original body, addresses and credentials. Registration requires an exact expected artifact hash. All metadata identity fields remain immutable; archive is the sole transition, active version1 to archived version2, retaining history.

Read is allowed to current Owner/Admin/Editor/Viewer with emails:read; creation/archive/reuse requires current Owner/Admin/Editor and emails:write. Billing is denied. Membership/key/workspace authority is rechecked by services before idempotent receipts are returned. Forced RLS and composite tenant foreign keys protect every row. Signed paging defaults25/max100; filter state is active(default) or archived, bound into cursor scope. Mutation bodies are strict and bounded by existing transport limits. Names/titles trim to1..160 characters; hashes are lowercase64hex; UUIDs canonicalized to lowercase.

Commands: GET/POST /v1/templates, GET /v1/templates/{id}, POST /v1/templates/{id}/archive {expected_version}, POST /v1/templates/{id}/remix {title,expected_version,expected_artifact_hash}. Registration body is {name,source_revision_id,expected_artifact_hash}. Mutations require original idempotency keys and return {template}, or existing derivation result {email,revision,lineage} for reuse. Archive and reuse serialize on the template row; archive rejects stale CAS, and new reuse of archived templates is refused. Replaying a previously successful reuse returns its original child and does not create work. Services use existing deriveEmail, preserving exact raw/custom source, frozen brand and source lineage while rechecking current asset authorization.

UI: add Templates navigation and catalogue with explicit empty/loading/error states, active/archived selection, signed load-more, frozen metadata, create separate draft and archive controls. An editor affordance saves the selected frozen revision with its exact hash; unsaved working content cannot become a template silently. Mutation receipts retain the exact original command/key in actor/workspace-scoped local storage before requests, fail closed if storage is unavailable, and preserve ambiguous results through navigation/reload/401. Changing input cannot silently replace a pending command; explicit retry targets the original command. Shared actor/workspace receipt subscriptions, in-flight guards and context epochs prevent stale controls, duplicate clicks or stale navigation. Explicit dismissal is allowed only after an authoritative TEMPLATE_ARCHIVED409 or VERSION_MISMATCH412 response to the original archive/remix command, or ASSET_NOT_READY409 to the original remix command, with that nonexecution classification stored against the exact original receipt. Unknown/authentication/network failures and malformed success remain unresolved. Successful historical receipts are returned before archive/remix callbacks by the service; these allowlisted callback rejections therefore establish nonexecution. ASSET_NOT_READY occurs during current asset validation inside derivation; the enclosing tenant transaction rolls back any partial child work and creates no successful receipt. This classification never applies to registration/archive or a generic 409. Other 4xx responses are not blanket dismissal permission. Viewer can browse but sees no mutation controls.

Qualification: meaningful RED/GREEN domain/storage/recovery tests; real restricted PostgreSQL isolation, immutable binding/CAS and same-key replay; actual HTTP/Chromium interrupted responses/repeated clicks/navigation/empty/errors/roles/390px; lint/type/API/build and full configured regression.
