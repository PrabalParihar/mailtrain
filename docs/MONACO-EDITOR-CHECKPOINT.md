Locations: `package-lock.json` entries for `monaco-editor` and `dompurify`; `src/code-editor/browser.ts:4,7`; installed upstream `node_modules/monaco-editor/esm/vs/base/browser/dompurify/dompurify.js:1` and `domSanitize.js:164-249`.

### M2 — Minor: empty compiled source has no explicit pending/empty explanation

Locations: `src/ui/editor.tsx:799-801` and `src/ui/html-code-editor.tsx:46-50`.

A labeled empty source field is visible and immutable, so this is a clarity/spec-completeness issue rather than authority or data-loss risk. ### M3 — Minor: successful stylesheet links accumulate across failed runtime-import retries

Locations: `src/ui/code-editor-loader.ts:13-18,31-38`.

If CSS loads successfully and the later module import fails, the loader clears `pending` but leaves the successful stylesheet link in the document. Each explicit enhanced retry appends another link for the same stylesheet. Shared successful CSS/runtime retention is appropriate across normal component unmounts; this failed-import retry path is the resource accumulation issue. This judgment is source-backed, not a separately executed retry reproduction. It has low impact and does not drop source; defer per the agreed Minor policy. A future fix can reuse a verified existing stylesheet or remove the attempt-owned link when later stages fail, while preserving shared successful users.

## Review rulings and retained design costs

1. **Current authority and integration: accepted.** The new raw callback routes only `raw_html` through the existing `update` function; parent checks current busy state/editing role and keeps draft versions, CAS, recovery and application Undo. Current `latest` props are refreshed in a layout effect, and the callback consults current read-only state rather than the initial option. Model `setValue` suppresses callbacks. The app keys the parent editor by workspace, actor and email (`src/ui/app.tsx:459-465`), which disposes old component state on scoped navigation. This supports the actual actor/workspace and Viewer proofs; it does not replace server authorization or establish instantaneous revocation without a server round trip.

2. **Delayed source, mode cancellation and fallback: accepted apart from I1.** The loader never constructs from a stale initially captured value; it reads the latest committed source immediately before creation. Cleanup sets cancellation before disposal, and late promises cannot resurrect a removed editor. A worker/runtime error gathers the current adapter source, retains it through the authorized callback when writable, disposes, and shows a truthful basic fallback. The 20-second component timeout can fall back before sequential loader stages finish; that is a deliberate usability bound, and cancellation guards preserve source. Failed `pending` loads can be retried. Read-only source does not gain a writable fallback. Real asset failures, actual HTML worker failure after successful preflight, cancellation and current-source adoption are demonstrated in the checked-in browser fixture and root's final browser log. Those results do not disprove I1.

3. **Source projection/history: accepted.** UTF16 offsets map across CRLF/LF/CR without normalizing untouched source. Explicit projection preserves a stripped leading BOM in Monaco while keeping basic-mode BOM editable. Descending nonoverlapping changes retain original offsets. Native undo/redo uses alternative-version snapshots for exact original source; controlled external resets clear the snapshot history and suppress spurious callbacks. The source history counts full UTF16 strings plus per-entry overhead and caps at 32 MiB; initial oversized source throws before model creation, and later budget exhaustion retains current source then falls back. Cost: long sessions/large source can leave enhanced mode, and new enhanced line endings follow Monaco while new basic endings are LF. Basic textarea diffing preserves untouched endings but is not a claim of arbitrary byte persistence through server save. Independent actual adapter reset/read-only/disposal proof and all 13 focused tests passed.

4. **Models, listeners and workers: accepted with scoped lifecycle claims.** Factory creation failures dispose the model; normal/idempotent disposal removes the container registry entry, listeners, instance, model and source history. Only a count diagnostic is exposed, with random model URIs and no workspace/email/actor/source identifiers in them. Real model counts reach zero on switches/navigation. Workers and language registrations are shared within the loaded runtime, rather than being terminated on every component unmount; Monaco's HTML WorkerManager idles its worker after two minutes with a 30-second check. This is an accepted bounded shared-runtime cost, not proof of instant worker termination or zero runtime memory. Worker error handlers reference the count-independent active-container registry, allowing truthful fallback. The retained service-registration RED was corrected before this immutable review, and the current primary browser pass has zero uncaught errors. DOM-dependent read-only synchronization is qualified for the pinned Monaco version and remains an upgrade cost.
