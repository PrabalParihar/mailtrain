# Private uploaded-media runtime

This is the bounded local REQ-020/021 foundation. All 65 PRD requirements and all 13 gates remain binding. Production publication, storage/CDN, retention/rights approval, AI providers, actual Outlook capture and economic policy remain unavailable. Native decode never implies malware cleanliness.

## Contracts and fixed mounts

`protocol.mjs` / `protocol.d.mts` export strict validators, profiles, limits and independent byte/hash/signature verification. Unknown fields, user paths/URLs, profile drift, missing outputs and a decoder `scan_clean` shortcut reject. Paths are generated by the trusted supervisor; filenames never come from the upload name.

Decoder stdin is `MediaProcessInput`. Mount one immutable file at `/input/source` read-only and a fresh empty directory at `/output` writable. Supply `MEDIA_IMAGE_DIGEST` equal to the actual configured immutable Docker image ID. Run `node /app/process.mjs`. It writes the same canonical receipt to stdout and `/output/receipt.json`; GIF creates `animation.gif` and selected composited `fallback.png`; PNG creates `static.png`; JPEG creates `static.jpg`. Outputs contain decoded/reencoded pixels and stripped source metadata. No source bytes become a renderable variant. The receipt is deterministic for the exact runtime, source and selection.

Scanner stdin is `MediaScanInput`, with `source` or fixed derivative filenames and exact byte counts/digests. Mount files under `/scan` and the completed signature snapshot at `/database`, both read-only. Supply `SCAN_IMAGE_DIGEST`. Run `node /app/scan.mjs`. Only an actual completed clean scan emits `MediaScanReceipt`. Source scan precedes decode; every derivative then receives a separate scan, with **90 seconds aggregate**, decoder 60 seconds and whole job 180 seconds enforced by the supervisor. No clean receipt is emitted for missing/stale/corrupt DB, hash mismatch, zero/skipped files, infection, limit, engine error, excessive logs, timeout or killed process. Receipt dates and image digests require scalar strings; arrays cannot pass via coercion. The snapshot directory rejects every unbound database entry before engine loading. Each job verifies all three official database signatures with actual `sigtool --info`, hashes the files, checks daily freshness and uses `--official-db-only=yes`. `--max-scantime=0` prevents ClamAV's internal per-file timeout from becoming assumed clean; the supervisor supplies the hard deadline.

Configure the supervisor with `MEDIA_DECODER_IMAGE`, `MEDIA_SCANNER_IMAGE`, `MEDIA_SCAN_DATABASE_ROOT=/tmp/lettercape-media-signatures-ddf036f5` and `MEDIA_SCAN_SNAPSHOT_SHA256=ddf036f5aec68a48d25395ac2c41285dedfca3a252a8baa16e316065cd1475e0`. Host runtime image variables differ from the fixed container `MEDIA_IMAGE_DIGEST`/`SCAN_IMAGE_DIGEST` bindings. Fresh builds resolve their own real IDs and require qualification; never reuse this paragraph as a future success claim. Earlier frozen images are retained so parallel tests do not lose pinned references.

The trusted supervisor independently validates the receipt, expected runtime digest, exact file set, regular-file type, bounded actual byte count, SHA256 and raster signatures before immutable storage or readiness. Image environment variables are profile bindings from trusted configuration, not proof supplied by the user.

## Versioned development limits

20 MiB source; static axes8192/pixels16,777,216; GIF canvas axes4096/pixels4,194,304; 200 frames and aggregate16,777,216 pixels; expanded RGBA64 MiB; metadata256 KiB; derivative20 MiB each/40 MiB total/48 MiB full output. PNG compressed scanline expansion is checked exactly (including Adam7) and capped at64 MiB plus8192 scanline bytes using maintained zlib inside the sandbox, before full Sharp decode. APNG, SVG, unknown formats, trailing polyglots, unsupported GIF extensions/reserved disposal and compressed/complex PNG ancillary metadata (`zTXt`, `iCCP`, `iTXt`) reject explicitly. JPEG supports grayscale/RGB, with orientation applied before output dimensions. Header validation is a gate; full native decode remains mandatory.

Decoder: non-root1001:1001, network none, read-only root, all capabilities dropped, no-new-privileges/default seccomp, 64 PIDs, 1 GiB/1 CPU, private noexec/nosuid128 MiB tmpfs, 60-second hard wall deadline and kill/reap. Sharp concurrency1 and cache disabled. Scanner: separate non-root100:101, same isolation, 3 GiB/2 CPUs/64 PIDs and bounded tmpfs. Neither job has application credentials, network credentials, Docker socket or public endpoint. Never decode hostile inputs in the host/API process.

## Build and database refresh

From the repo root:

```sh
docker build -f media/Dockerfile -t lettercape-media:dev .
docker build --platform linux/amd64 -f media/scan.Dockerfile -t lettercape-media-scan:dev .
```

Node24.12.0, exact Sharp0.35.5/libvips8.18.7 and upstream base-image digests are pinned. `npm ci --ignore-scripts` actually loads the prebuilt native dependency in the build; optional native packages are not assumed installed.

Official `clamav/clamav:1.4.6_base` has no ARM64 manifest. Scanner is explicitly AMD64 under emulation on this ARM64 Docker host; this is measured, not described as native ARM64. Do not change global Docker settings to conceal that distinction. Docker Desktop denied Documents-directory bind mounts here; use a generated trusted `/tmp` spool root. No host software install is needed.

`node /app/scan.mjs --prepare` is a **separate setup-only** one-shot FreshClam process. Give it only a fresh dedicated writable `/database` directory and private tmpfs, no sources or credentials. Setup needs network to the official configured `database.clamav.net` mirror / `current.cvd.clamav.net` DNS; it is never the offline scan job. The default official registry downloads require no paid account. After successful updates of main/daily/bytecode, it verifies signatures and writes `snapshot.json`. Promote the completed directory atomically and mount read-only for jobs. No refresh can mix an in-flight job's databases.

Snapshot shape is `{version:1,profile,files:[{filename,sha256,bytes}],snapshot_sha256,daily_built_at,verified_at}`. Ordered files are main/daily/bytecode, each exactly one `.cvd` or `.cld`. Snapshot digest is SHA256 of `JSON.stringify(files)`. Daily age must be at most48 hours, a development freshness profile rather than a production update SLA. A custom fixture DB cannot establish readiness.

## Qualification and evidence

Set `MEDIA_DECODER_IMAGE`, `MEDIA_SCANNER_IMAGE` and `MEDIA_SCAN_DATABASE_ROOT` to the local qualified images and signed snapshot. The default dev tags are resolved to immutable IDs before each proof. Retained stdout, receipts, CPU/cgroup-memory measurements, fixture pixels and profiles go to ignored `output/media-runtime-evidence/qualification.json`; failures retain `qualification-red.json`. No fixture is sent publicly.

Fixtures are original synthetic explicit RGBA grids.
